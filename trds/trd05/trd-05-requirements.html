TRD-05: Connection Management

Requirements — Limen RDMA Transport Project
Depends on: TRD-04  |  Difficulty: Medium-High  |  Estimated: 4–5 sessions

Objective

Extend the RAII layer with wrappers for the event channel, the connection identifier, and the event itself. Establish connections by IP address using the RDMA connection manager, carrying an application payload in the handshake. Port limen_pingpong onto it, deleting its TCP side channel and its hand-rolled queue pair bringup entirely.

What This Is Not

No changes to data transfer. Posting, polling, and completion handling are untouched; the queue pair the CM hands you behaves exactly like the one you built by hand, and TRD-03's test suite must pass against the ported program.

No concurrency. One connection at a time, one event at a time, blocking event retrieval. A server holding many connections needs a non-blocking event loop, which is a different topic.

No reconnection, retry, or resolution-timeout policy. All are guesswork without a use case.

limen_connect is not deleted

limen_connect keeps its hand-rolled TCP exchange and its manual state machine, and the TRD-02 suite must keep passing against it unchanged. It is the reference for what the CM hides. Only limen_pingpong is ported.

Interface

New wrappers under include/limen/cm.hpp, namespace limen, satisfying the same contract as TRD-04's types.

namespace limen {

class EventChannel {                       /* rdma_event_channel * */
public:
    EventChannel() noexcept = default;
    EventChannel(std::nullptr_t) = delete;
    static EventChannel create();           /* throws VerbsError */
    /* five special members, move-only, noexcept dtor */
    rdma_event_channel *get() const noexcept;
    int close() noexcept;
};

class ConnectionId {                        /* rdma_cm_id * */
public:
    ConnectionId() noexcept = default;
    ConnectionId(EventChannel& ch, rdma_port_space ps);   /* creates */
    static ConnectionId adopt(rdma_cm_id *id) noexcept;   /* takes an existing one */
    /* five special members, move-only, noexcept dtor */
    rdma_cm_id *get() const noexcept;
    ibv_qp     *qp()  const noexcept;       /* nullptr before create_qp */
    int close() noexcept;
};

class Event {                               /* rdma_cm_event *, acked on destruction */
public:
    explicit Event(EventChannel& ch);       /* blocks; throws VerbsError */
    ~Event() noexcept;                      /* acknowledges */
    Event(const Event&)            = delete;
    Event& operator=(const Event&) = delete;
    Event(Event&&) noexcept;
    Event& operator=(Event&&) noexcept;

    rdma_cm_event_type type()   const noexcept;
    const char        *name()   const noexcept;   /* rdma_event_str */
    int                status() const noexcept;
    rdma_cm_id        *id()     const noexcept;

    /* Copies at most `len` bytes of private data out. Returns bytes copied.
       There is no accessor returning the raw pointer, by design. */
    std::size_t copy_private_data(void *dst, std::size_t len) const noexcept;

    int ack() noexcept;                     /* idempotent; dtor calls it */
};

struct ConnInfo {                            /* the handshake payload */
    std::uint64_t addr;
    std::uint32_t rkey;
    std::uint32_t length;
};                                           /* 16 bytes; must fit in 56 */

} /* namespace limen */

Technical Requirements

R1 — EventChannel

Wrap rdma_create_event_channel and rdma_destroy_event_channel, satisfying TRD-04's static contract: move-only, noexcept destructor, idempotent close(), valid empty state.

The channel must outlive every identifier created from it and every event retrieved from it. Express that through member declaration order wherever both appear.

Stuck? → Hints H1

R2 — ConnectionId, With Adoption

Two ways to obtain one, and the type must support both:

  • A constructor calling rdma_create_id against a channel with port space RDMA_PS_TCP.
  • A static adopt() taking an rdma_cm_id * that already exists and assuming responsibility for destroying it.

Adoption exists because on a connect request the library creates the identifier and hands it to you through the event.[1][3] None of TRD-04's five wrappers needed this, and adding it is the first evidence of whether that layer generalises.

Exactly one object destroys any given identifier. The listener and the adopted connection are two distinct identifiers with two distinct owners; the event does not retain ownership of the one it delivered.
Stuck? → Hints H2

R3 — Event, Acknowledged by Destruction

Wrap rdma_get_cm_event and rdma_ack_cm_event so that acknowledgement happens in the destructor and therefore on every exit path, including exceptions.

This is not tidiness. An unacknowledged event blocks the destruction of the associated identifier,[1][6] so a single missed acknowledgement on an error path produces a hang at teardown with no diagnostic and no obvious cause.

ack() is idempotent and the destructor calls it. type(), name(), status(), and id() are accessors. There is no accessor returning the raw event pointer.

Stuck? → Hints H3

R4 — Private Data Copied Out, Never Referenced

Event exposes only copy_private_data(void *dst, std::size_t len), which copies at most len bytes and returns how many were available. It must not expose the underlying pointer.

The buffer is deallocated by the acknowledgement,[1] and because R3 makes the acknowledgement automatic there is no visible call to notice you are reading past. Removing the pointer from the interface makes the dangling read inexpressible rather than merely discouraged.

Use private_data_len to determine how much was actually sent. The received buffer may be larger than the payload, with the remainder zeroed,[1] so its size proves nothing.

Stuck? → Hints H4

R5 — Client Connection Path

Resolve the address, wait for ADDR_RESOLVED; resolve the route, wait for ROUTE_RESOLVED; create the queue pair; connect with the payload, wait for ESTABLISHED.[2]

Print a cm: event line for every event received, naming it with rdma_event_str. An event other than the expected one at any step is fatal: report the name and the status field and exit 7.

Impose a timeout on address resolution. rdma_get_cm_event blocks indefinitely by default,[1] and an unreachable peer would otherwise hang with no output.

Stuck? → Hints H5

R6 — Server Listen and Accept Path

Bind, listen, wait for CONNECT_REQUEST. Adopt event->id as a second identifier, copy the payload out, create the queue pair on the adopted identifier, and accept with your own payload. Wait for ESTABLISHED.

rdma_accept is called on the adopted identifier, never on the listener.[3] The listener stays open.

Print cm: event CONNECT_REQUEST (new id adopted) so that the ownership transfer is visible in the output rather than implied.

Stuck? → Hints H6

R7 — Handshake Payload

Exchange the receive region's address, remote key, and length using ConnInfo, in both directions.

Fixed-width members converted to network byte order. A packed struct with native padding and native endianness works between two identical nodes and is broken by construction.

Assert at compile time that sizeof(ConnInfo) <= 56. The connect direction is limited to 56 bytes and the accept direction to 196;[2][3] a payload sized against the larger limit fails in the other direction, and the assertion is what stops that from being discovered at runtime.

Print the received values on the peer: line. TRD-06 is the first rung that uses them, and seeing them arrive correctly here is what makes that rung debuggable.

Stuck? → Hints H7

R8 — Connection Parameters

Populate rdma_conn_param: private_data and its length, responder_resources and initiator_depth clamped against the device's max_qp_rd_atom and max_qp_init_rd_atom, retry_count, and rnr_retry_count.

TRD-03's --rnr-retry flag maps to rnr_retry_count. It is a 3-bit value and 7 still means infinite.[2] Do not set qp_num; it is ignored once a queue pair exists on the identifier.[3]

Record in docs/cm-notes.md that the minimum RNR timer is now fixed at 0, meaning 655 ms,[2] and that this is roughly a thousandfold increase over the value TRD-02 set. TRD-03's finite-retry experiment will take visibly longer after this rung, and the note is what stops that being mistaken for a defect.

Stuck? → Hints H8

R9 — Disconnection

After the ping-pong completes, the client calls rdma_disconnect. Both sides wait for DISCONNECTED and report it.

Both sides must handle receiving DISCONNECTED unprompted — the peer may go first. Handle TIMEWAIT_EXIT by acknowledging and continuing rather than treating it as unexpected; it reports that the queue pair has left timewait and may be reused,[1] which this program does not do.

Stuck? → Hints H9

R10 — Delete the Side Channel

Remove from limen_pingpong: the listening socket, the connecting socket, the text encoding of the four bringup values, the ready-marker exchange, and all three ibv_modify_qp calls with their attribute structures.

The program must not name socket, bind, listen, accept, connect, or ibv_modify_qp anywhere. The suite greps for this.

The ready-marker exchange is subsumed: ESTABLISHED arrives only after both sides have completed the handshake, so receives posted before rdma_connect and rdma_accept are in place before any message can arrive.

Stuck? → Hints H10

R11 — Teardown, Regressions, Leaks

Destruction order now includes three more resources. Events are released as they go out of scope; the identifier before the channel; the queue pair before the identifier that owns it. Express what you can through declaration order and document what you cannot.

The teardown: line gains id= and channel= stages.

Regressions: the TRD-02 suite must still pass against the untouched limen_connect, and the TRD-03 suite must pass against the ported limen_pingpong — the latter with no modification to the suite, since observable behaviour is unchanged.

Leak checks: zero bytes definitely lost on the success path, on a connection refused by an absent peer, and on the finite-retry RNR path.

Stuck? → Hints H11

Deliverables

  • include/limen/cm.hpp and src/cm.cpp — the three wrappers and ConnInfo.
  • tests/cm_static_contract.cpp — the ownership assertions for the new types, plus the ConnInfo size assertion.
  • tests/no_raw_private_data.cpp — a program attempting to obtain the raw pointer, which the suite requires to fail compilation.
  • limen_pingpong, ported. limen_connect, untouched.
  • scripts/trd-05-tests.sh, executable, passing.
  • docs/cm-notes.md recording: the R8 note about the imposed RNR timer, a full event trace from both sides, and one paragraph on what the TRD-04 layer needed in order to accommodate these three resources.
  • Written answers to the comprehension questions.

What Comes Next

TRD-06 uses the address and remote key this rung delivers. RDMA_WRITE and RDMA_READ name a remote buffer directly, and the values printed on the peer: line are exactly what makes that possible — which is why R7 requires them printed even though nothing consumes them yet.

It is also the rung where the remote CPU stops participating, and where the access flags set at the INIT transition in TRD-02 and now supplied through the CM finally matter.
