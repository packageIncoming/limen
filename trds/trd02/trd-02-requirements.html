TRD-02: Queue Pairs and the State Machine

Requirements — Limen RDMA Transport Project
Depends on: TRD-01  |  Difficulty: High  |  Estimated: 4–6 sessions

Objective

Build limen_connect: a two-node program that creates a completion queue and a reliable-connected queue pair, exchanges endpoint parameters with a peer over TCP, drives the queue pair from RESET to RTS through all three transitions, and verifies the result by querying the queue pair back.

What This Is Not

Nothing is transmitted over RDMA. No work requests are posted, no completions are polled, and the registered buffer from TRD-01 is carried along unused. The queue pair ends the program connected and idle — a state a real transport would never occupy, and the right place to stop while the state machine is what is being learned.

The TCP side channel is disposable. It needs no framing, no versioning, and no reconnection logic, because TRD-05 deletes it. Time spent making it robust is time wasted.

Still no C++ resource management. TRD-04 is where that arrives, and the seven-handle teardown this rung produces is the argument for it.

Interface

./build/limen_connect -d <device> -g <gid_index> [-p <port>] [-t <tcp_port>] [-s <bytes>] [<peer>]
ArgumentEffect
-d <device>RDMA device to open. Required.
-g <gid_index>Index into the local GID table. Required — there is no safe default.
-p <port>RDMA port number. Default 1.
-t <tcp_port>TCP port for the parameter exchange. Default 18515.
-s <bytes>Buffer size to allocate and register. Default 4096.
<peer>Peer address. Absent means server, present means client — the same convention the reference tools use.

Exit codes: 0 success, 1 usage error, 2 device not found, 3 verbs operation failed, 4 side-channel failure.

Technical Requirements

R1 — Completion Queue Sized From Device Attributes

Create a completion queue with capacity for at least the sum of the send and receive queue depths chosen in R2. Clamp the request to max_cqe from the device attributes; do not use a literal constant as the ceiling.

Print the cq: line reporting the granted cqe and the value requested. Providers round up, and the report exists so you observe that rather than assume it did not happen.

Stuck? → Hints H1

R2 — Reliable-Connected Queue Pair

Create an IBV_QPT_RC queue pair against the protection domain, using the completion queue from R1 for both send and receive.

Clamp each of max_send_wr, max_recv_wr, max_send_sge, and max_recv_sge against the corresponding device limits before the call. After the call, print the qp: line reporting the values the provider actually granted — read them back out of the structure you passed, which the call writes into.

Stuck? → Hints H2

R3 — Local Endpoint Identity

Assemble the four values the peer needs: the queue pair number from the created queue pair, a randomly chosen 24-bit packet sequence number, the GID at the index given by -g, and the port's LID.

Print the local: line. Render the GID in the conventional colon-separated hexadecimal form so it can be compared by eye against show_gids output.

A GID that prints as all zeroes means the index selects an unpopulated table entry. The program must detect this and exit 3 with a message naming the index, rather than proceeding to a transition that will fail for a reason the error will not identify.
Stuck? → Hints H3

R4 — Side-Channel Exchange

Exchange the R3 values with the peer over TCP. Server binds and accepts; client connects. Both must send their own values and receive the peer's before either proceeds.

Encode as text, one line, fields separated by a single character. Do not transmit a struct — layout and endianness differ across machines and a text line can be read directly out of a packet capture when the exchange is what broke.

Print the remote: line in the same format as local:. A side-channel failure exits 4, distinctly from a verbs failure, so that the two classes are distinguishable without reading the message.

Stuck? → Hints H4

R5 — RESET → INIT

Transition the queue pair to INIT with the mask required for the reliable-connected service type.[1]

Set qp_access_flags to permit incoming remote reads and writes. TRD-06 requires this, and the value cannot be changed on a connected queue pair without transitioning back through RESET and repeating the entire bringup.

Print state: RESET -> INIT ok.

Stuck? → Hints H5

R6 — INIT → RTR

Transition to RTR with the required mask, supplying the peer's queue pair number and sequence number from R4, the path MTU from the port attributes, and a fully populated address vector.

The address vector must set is_global, the destination GID, the source GID index, the hop limit, and the port number. Section 8 of the Prior Knowledge document explains which of those is the peer's value and which is an index into your own table — they are not symmetric and confusing them is the second most common failure here.

Print state: INIT -> RTR ok. This is the transition that fails; R10 governs what happens when it does.

Stuck? → Hints H6

R7 — RTR → RTS

Transition to RTS with the required mask, supplying your own sequence number, the acknowledgement timeout, both retry counts, and the outstanding-read limit clamped against max_qp_rd_atom.

Print state: RTR -> RTS ok.

Which sequence number goes where

rq_psn at R6 takes the peer's number. sq_psn here takes yours. Crossing them is accepted by both transitions without error and surfaces in TRD-03 as a transfer that never completes.

Stuck? → Hints H7

R8 — Verify State

After the final transition, query the queue pair back and print verify: qp_state=RTS. Any other state exits 3.

This is the rung's gate. With nothing transmitted, a queue pair reporting RTS on both ends is the only available evidence that bringup succeeded — and it is also the only way to detect a queue pair that has silently fallen into the error state, which is externally indistinguishable from one sitting idle.

Stuck? → Hints H8

R9 — GID Index Validation

Require -g explicitly; do not default it. Validate the supplied index against gid_tbl_len from the port attributes and exit 1 if it is out of range.

If the GID at that index is all zeroes, exit 3 with a message naming the index and pointing at the enumeration procedure from TRD-00. A silently wrong GID index is the single most expensive mistake available at this rung, because the resulting failure appears at R6 with an error that does not mention GIDs.

Stuck? → Hints H9

R10 — Transition Failure Diagnosis

A failed transition must print the diagnostic block shown in the Output Contract before exiting 3: the symbolic errno with its description, the attribute mask rendered as pipe-separated flag names, and every attribute the mask names with the value actually passed.

For a failed RTR transition specifically, the block must include the address vector fields and the RoCE hint. This is not decoration. EINVAL from this transition carries no information about which of eleven fields was wrong, and a program that prints only the errno leaves you comparing your code against a manual page line by line.

Every verbs call is checked using the convention its own manual page documents. ibv_modify_qp() returns 0 or an errno value; testing for -1 produces a check that never fires.[1]

Stuck? → Hints H10

R11 — Teardown Order

Destroy in reverse creation order: queue pair, completion queue, memory region, protection domain, context. The queue pair must go before the completion queue it references, and both before the protection domain.

Print the teardown: line reporting each stage as ok, n/a, or the symbolic errno. Every exit path unwinds what it created, including the failure paths from R6 and R10. Running under valgrind --leak-check=full must report zero bytes definitely lost on both a successful run and a deliberately failed one.

Stuck? → Hints H11

What Comes Next

TRD-03 posts the first work request into the queue pair this rung connected. Receives must be posted before the peer sends, which is where the receiver-not-ready condition becomes concrete rather than a parameter you set at R6. The registered buffer carried unused through this rung becomes the buffer that is actually transferred, addressed by the local key printed in TRD-01.

The five-handle teardown in R11 becomes seven in TRD-03 and continues growing. TRD-04 replaces it.
