TRD-01: Context, Protection Domain, Memory Registration

Requirements — Limen RDMA Transport Project
Depends on: TRD-00  |  Difficulty: Medium  |  Estimated: 3–4 sessions

Objective

Build limen_devinfo: a diagnostic program that enumerates RDMA devices, opens one, reports its device and port attributes, allocates a protection domain, registers a memory region, prints the resulting keys, and tears everything down in the correct order with every return value checked.

What This Is Not

There is no connection, no queue pair, no peer, and nothing transmitted. The program runs on one node and never touches the network. The keys it prints go nowhere — TRD-05 builds the exchange that carries them and TRD-06 is the first rung that uses one.

There is also no C++ resource management yet. Write this in plain C or in C++ with manual cleanup. TRD-04 exists to replace that cleanup, and doing it early removes the experience that makes TRD-04 land.

Interface

./build/limen_devinfo [-d <device>] [-p <port>] [-s <bytes>] [--check-access] [-h]
ArgumentEffect

Technical Requirements

R1 — Build Target and Argument Handling

Add a limen_devinfo executable target to the build, linking libibverbs. It must build with no warnings under -Wall -Wextra.

Parse the arguments in the Interface table. An unknown argument, a flag missing its value, or a -s or -p value that does not parse as a positive integer must print a usage line to stderr and exit 1. -h prints usage to stdout and exits 0.

Stuck? → Hints H1

R2 — Device Enumeration

With no device named, retrieve the device list and print one device: line per entry giving the name and the GUID as a 16-digit hexadecimal value, followed by a devices: count line. Exit 0.

Distinguish two cases that are not the same: the call failing, which is a verbs error and exits 3, and the call succeeding with a count of zero, which means no RDMA devices are registered with the kernel and exits 2 with a message to stderr naming the likely cause.

Release the device list. It must not leak on any path, including the ones that exit early.

Stuck? → Hints H2

R3 — Open a Named Device

With -d, find the entry whose name matches exactly and open it. A name that matches nothing exits 2 with a stderr message listing the names that are available — a user who mistyped a device name should not have to run the program a second time to discover the right one.

Free the device list once the context is open. The context remains valid after the list is released.

Stuck? → Hints H3

R4 — Report Device Attributes

Query the device and print every field shown in the Report mode block: guid, fw_ver, phys_port_cnt, max_qp, max_qp_wr, max_cq, max_cqe, max_mr, max_mr_size, max_sge, and max_qp_rd_atom.

These are the values TRD-02 and TRD-03 must size against. Print them as retrieved; do not substitute defaults for fields the provider reports as zero.

Stuck? → Hints H4

R5 — Report Port Attributes

Query the requested port — default 1 — and print state, link_layer, active_mtu, max_msg_sz, and gid_tbl_len.

state, link_layer, and active_mtu are enumerations and must be printed as their symbolic names, not their integers: PORT_ACTIVE rather than 4, Ethernet rather than 2, and the MTU in bytes rather than its enum ordinal. A port number outside the range reported by phys_port_cnt is a usage error and exits 1.

Stuck? → Hints H5

R6 — Allocate a Protection Domain

Allocate a protection domain on the open context and print pd: allocated. Failure exits 3 with the reason.

Stuck? → Hints H6

R7 — Register a Memory Region

With -s, allocate a buffer of that many bytes, register it against the protection domain with LOCAL_WRITE, REMOTE_READ, and REMOTE_WRITE, and print the mr: line with the region's address, length, local key, remote key, and the access flags rendered as a pipe-separated list of their symbolic names.

Print the address and length as reported in the returned structure rather than the values you passed in. They should agree; printing what the API returned is what makes it possible to notice when they do not.

Stuck? → Hints H7

R8 — Access Flag Constraint

With --check-access, attempt a second registration of a small buffer requesting REMOTE_WRITE without LOCAL_WRITE. This combination is invalid and the call is required to reject it.[3]

Print the access-check: line naming the symbolic errno and its description. If the registration unexpectedly succeeds, deregister it, report the anomaly to stderr, and exit 3 — a provider that accepts an invalid combination is a finding, not a pass.

This requirement exists so that you meet the constraint deliberately, with the manual page open, rather than accidentally in TRD-06 when a buffer will not register and the reason is three flags away.

Stuck? → Hints H8

R9 — Graceful Registration Failure

A registration that fails must produce the diagnostic block shown in the Output Contract: the symbolic errno and its description, the requested size, the current soft RLIMIT_MEMLOCK value, and a remediation hint. Exit 3.

Retrieve the limit programmatically.[4] Render an unlimited value as unlimited rather than as its numeric representation. The program must not crash, must not dereference the null return, and must still perform teardown of everything it did successfully create.

On a host whose locked-memory limit is unlimited, a large registration may succeed rather than fail. That is not a defect in your program. The test suite selects a size relative to the limit it observes, and skips this check when no limit applies.
Stuck? → Hints H9

R10 — Teardown and Error Discipline

Every verbs call must be checked using the convention its own manual page documents — see section 10 of the Prior Knowledge document, which tabulates three different conventions in use across the functions this TRD calls. A checked call whose failure is reported to stderr and reflected in the exit code satisfies this; an unchecked call does not, even where failure is implausible.

Teardown runs in reverse creation order: memory region, then protection domain, then context. Print the teardown: line reporting the outcome of each, using n/a for objects that were never created and ok or the symbolic errno otherwise.

Every exit path unwinds what it created. A failure at R7 must still deallocate the protection domain and close the context. Running under valgrind --leak-check=full must report zero bytes definitely lost, on both the success path and a failure path.

Stuck? → Hints H10

Deliverables

  • src/limen_devinfo.c (or .cpp) and any headers it needs under include/limen/.
  • A CMakeLists.txt building limen_devinfo with -Wall -Wextra and linking libibverbs.
  • scripts/trd-01-tests.sh, executable, passing.
  • docs/device-attrs.md recording the full report-mode output from your fabric. TRD-02 sizes its queues against these numbers and must not guess them.
  • An updated README.md documenting the program's usage and exit codes.
  • Written answers to the comprehension questions.

What Comes Next

TRD-02 creates a completion queue and a reliable-connected queue pair from the protection domain allocated here, sizes both against the attributes captured in R4, and drives the queue pair by hand through its state machine to Ready-To-Send. It is the hardest rung in the ladder.

The registered region built here becomes the buffer that TRD-03 sends from and receives into, addressed by the local key printed in R7. The remote key printed alongside it stays unused until TRD-06, where it is what a peer must hold to write into this memory without asking.
