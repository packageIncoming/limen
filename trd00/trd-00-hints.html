TRD-00: Fabric Up

Hints — Limen RDMA Transport Project
Level 1 = nudge  |  Level 2 = stronger push  |  Try Level 1 for 15+ minutes before escalating

Level 1 points at the right place. Level 2 names the mechanism.

These hints cover the requirements only. Setup problems are not hinted at — the Setup section of the Requirements document has the exact commands, and its Troubleshooting table covers the ways it goes wrong. If you are fighting the environment, you are in the wrong document.

H1 — Determine the Correct GID Index (R1)

Level 1

Two pieces of information exist for every table entry: the GID value itself, and the entry’s type. Both live in sysfs under the device, in sibling directories. The type is what distinguishes the candidates, and section 8 of the Prior Knowledge document explains what the two types mean and why only one of them is routable.

The GID for an IPv4 address contains that address in hexadecimal at the end. Convert your node’s address by hand and look for it — that plus the type narrows eight entries to one.

A tool from the benchmark package also prints the table in readable form, if you would rather read than derive.

Level 2
for i in $(seq 0 7); do
  t=$(cat /sys/class/infiniband/rxe0/ports/1/gid_attrs/types/$i 2>/dev/null)
  [ -n "$t" ] && echo "$i  $t  $(cat /sys/class/infiniband/rxe0/ports/1/gids/$i)"
done

Or simply show_gids, which comes with perftest.

Select the entry whose type reads RoCE v2 and whose GID ends in your dotted-quad in hex — 10.0.0.1 appears as ...:0a00:0001, since 10 is 0x0a and 1 is 0x01. Typically index 1 or 3.

The entries you are rejecting are RoCE v1 ones, which encapsulate directly in Ethernet with their own EtherType and cannot be routed, and any IPv6 entries. Index 0 is very often RoCE v1, which is why defaulting to it fails with an error that never mentions GIDs.

Record all of it, not just the answer — R1 asks for the reasoning because the reasoning is what transfers.

H2 — Raw Verbs Transfer (R2)

Level 1

The tool runs in two modes distinguished by whether you give it a peer address: with one it is a client, without one it is a server. Start the server first and leave it running.

It also needs the GID index from R1. If it fails, do not try other indices at random — go back and check your R1 reasoning, because an index that fails here means the reasoning was wrong and you want to know how.

Level 2
# node A (10.0.0.1) — server, start first
ibv_rc_pingpong -d rxe0 -g 3

# node B — client
ibv_rc_pingpong -d rxe0 -g 3 10.0.0.1

Substitute your index for the 3. Both sides need the same flag.

Once it passes, read the source before moving on — roughly 800 lines, and it is the direct skeleton of TRD-02 and TRD-03.[1] Find it in the rdma-core repository under libibverbs/examples/rc_pingpong.c. Annotating it now is the best preparation available for those rungs.

H3 — Connection Manager Transfer (R3)

Level 1

This tool takes an address rather than a device, and server and client are selected by explicit flags rather than by argument position. Read the usage text.

Note the asymmetry with H2 as you type the two commands: both sides here are given the same address. That is a clue toward the paragraph R3 asks for.

For that paragraph: compare your two command lines side by side. One argument you had to supply in R2 is absent here. Ask what determined it instead, and what that component must have done in order to know.

Level 2
# node A
rping -s -a 10.0.0.1 -v -C 10

# node B
rping -c -a 10.0.0.1 -v -C 10

-s server, -c client, -a the server’s address on both sides, -v verify payload, -C 10 ten iterations.

The difference R3 wants: no -g. The connection manager resolved the address to a device, a port, and the correct GID index on your behalf — the same index you derived by hand in R1. That resolution is the primary service it provides, and it is why TRD-05 deletes a large amount of code you will have written by then.

If this fails while R2 passed, the fault is isolated to the connection-manager path: check lsmod | grep rdma_ucm and that /dev/infiniband/rdma_cm exists.

rping.c in librdmacm/examples/ is the structural model for TRD-05.[1]

H4 — See RoCEv2 on the Wire (R4)

Level 1

Capture on the RDMA interface while a transfer runs. You need two terminals on the same node: one capturing, one running the client.

Filter on the port rather than capturing everything, or the ping-pong’s own side channel and your SSH session will drown the output.

Bound the capture with a packet count so it exits on its own rather than needing a signal.

Level 2
# terminal 1 — start this first
sudo tcpdump -i enp0s8 -n udp port 4791 -c 20

# terminal 2 — then run a transfer
ib_send_bw -d rxe0 10.0.0.1

Expect lines showing UDP datagrams between your two addresses with destination port 4791. To see the payload structure, add -X for a hex dump — the bytes after the UDP header are the InfiniBand transport headers described in section 8.

For the explanation R4 asks for, the shape of the answer is: the capture works here because the software provider is implemented in the kernel and the packets pass through the ordinary network stack, where a sniffer can see them. A hardware adapter builds and transmits these packets itself without involving the host stack, so the same command shows nothing — which is why practitioners use vendor tools such as ibdump or a switch mirror port instead.

Write that in your own words. The point is that the capture’s success is measuring the absence of kernel bypass on this fabric.

H5 — Measure the Fabric (R5)

Level 1

Same server-and-client pattern as H2: no address means server, an address means client. Start the server first.

Both tools print a table with a header row and data rows. The bandwidth tool reports both a peak and an average — take the average, since peak over a short run is noise. The latency tool reports several percentiles; the median and the 99th are the two worth recording, and the mean is the one to ignore.

Do not investigate the numbers. Section 9 explains why they are low and the explanation is structural rather than fixable.

Level 2
# bandwidth — server first
ib_send_bw -d rxe0                      # node A
ib_send_bw -d rxe0 10.0.0.1             # node B

# latency — server first
ib_send_lat -d rxe0                     # node A
ib_send_lat -d rxe0 10.0.0.1            # node B

The bandwidth data row carries, in order: message size, iterations, peak bandwidth, average bandwidth, message rate. Take the fourth column. The latency output includes t_med and a 99th-percentile column.

H6 — Compare Against TCP (R6)

Level 1

Server and client again, over the same interface, so the comparison is like for like.

Before you run it, write down what you expect. Then run it. The gap between the two is the useful part of this requirement, whichever direction it goes.

For the explanation, the question to answer is: on this fabric, what work does an RDMA transfer do that a TCP transfer does not? Section 9 has the answer, and it is not the answer most people expect before measuring.

Level 2
# node A
iperf3 -s

# node B
iperf3 -c 10.0.0.1 -t 10

Take the sender’s figure and convert units so the two are comparable — iperf3 reports Gbit/sec and ib_send_bw reports MB/sec. One Gbit/sec is 125 MB/sec.

Expect TCP to win, possibly by a lot. That is the correct result on soft-RoCE and it surprises nearly everyone.

The reason: TCP over a virtual link is a well-optimised kernel path with segmentation offload and years of tuning behind it. Soft-RoCE runs the entire InfiniBand transport in software — queue-pair state, sequence numbers, acknowledgements, encapsulation — and then hands the result to that same kernel network stack. It is doing strictly more work over the same wire.

Which is exactly the point. RDMA’s advantage comes from hardware performing that transport work and writing directly into memory. Remove the hardware and you keep all the protocol cost and none of the benefit. If you had measured only the RDMA number you might have concluded the technology is slow; the comparison shows instead that this implementation is slow, for a reason that names precisely what the hardware would have contributed.

Write two to four sentences saying that, in your own words, with your own numbers.

H7 — Capture the Device Attributes (R7)

Level 1

One command with a verbosity flag produces everything. Append it rather than transcribing fields by hand, then pull out the nine named ones into a short summary above it.

The fabric configuration half of this requirement is a note to your future self. You will reboot, the link will be gone, and you will want the exact commands rather than a reconstruction.

Level 2
{
  echo
  echo '## ibv_devinfo -v -d rxe0'
  ibv_devinfo -v -d rxe0
} >> docs/baseline-rxe.md

Then a summary block at the top with the nine fields, so TRD-01 and TRD-02 can find them without reading two hundred lines.

For docs/fabric.md:

# Fabric

Node A: 10.0.0.1   Node B: 10.0.0.2
RDMA interface: enp0s8   (NAT is on enp0s3 — do not use it)
GID index: 3   (RoCE v2, IPv4-mapped)
Firewall: ufw disabled on both nodes

## Recreate after reboot (both nodes)
sudo ip link set enp0s8 up
sudo ip addr add 10.0.0.1/24 dev enp0s8     # .2 on node B
sudo modprobe rdma_rxe rdma_ucm
sudo rdma link add rxe0 type rxe netdev enp0s8

H8 — Repository and Build System (R8)

Level 1

Two CMake commands find things: one searches for a library file, the other for a header directory. Both accept a flag that turns a failure into a hard configuration error rather than a silently empty variable — and R8 wants that flag on all four lookups, because a silently empty variable defers the failure to TRD-01, which is what this rung exists to prevent.

Git will not track an empty directory. Decide how the empty source directories survive the initial commit.

Level 2
cmake_minimum_required(VERSION 3.16)
project(limen LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)

find_library(IBVERBS_LIB ibverbs REQUIRED)
find_library(RDMACM_LIB  rdmacm  REQUIRED)
find_path(IBVERBS_INCLUDE_DIR infiniband/verbs.h REQUIRED)
find_path(RDMACM_INCLUDE_DIR  rdma/rdma_cma.h    REQUIRED)

message(STATUS "libibverbs: ${IBVERBS_LIB}")
message(STATUS "librdmacm:  ${RDMACM_LIB}")

# TRD-01 adds the first target here.

Verify with cmake -S . -B build. Both status lines must print real paths; a failing find_library means the development package from S5 is missing.

Place a .gitkeep in include/limen/, src/, scripts/, and tests/ so the layout survives the first commit. Add build/ and compile_commands.json to .gitignore.

The Tool Boundary

Reach for the diagnostics before reaching for a chat window. On this rung that means ibv_devinfo, tcpdump, dmesg, and the two troubleshooting tables; on later rungs it will mean gdb, valgrind, and completion status codes. Building the habit now is why the later rungs stay tractable, because RDMA’s error reporting is poor enough that a practitioner without diagnostic instincts is simply stuck.

An AI assistant is appropriate for reviewing code once it works, clarifying a concept a document left unclear, and grading comprehension answers. It is not appropriate for writing or debugging the implementation.
